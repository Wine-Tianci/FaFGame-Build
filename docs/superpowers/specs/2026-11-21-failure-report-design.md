# 单文件失败报告

用户要求把先前列出的启动、Git、导入、测试、导出和导出包运行失败整合到一个日志。采用每次失败生成 failure-report.log，先列错误摘要、分支/模式/版本、阶段和调用栈，再完整汇总该次 stdout/stderr/Godot 日志及 process.json。相较截取错误行或压缩日志目录，纯文本单文件便于直接打开、搜索和分享，并保留上下文。

新增 Failure-Report.ps1 共享报告函数，按白名单仅读取日志目录的直接子文件，保留原始日志，不扫描源码、用户配置和 secrets。读取失败以报告节记录。启动报告遮盖已知本机初始密码、API Token 和 Authorization 头；失败报告生成失败时不得覆盖原始异常。仅向校验过、与源码隔离的工具/构建目录写入。

Build-Windows.ps1 捕获错误时生成运行目录/failure-report.log；Jenkins 不成功时通过 New-BuildFailureReport.ps1 汇总至 builds/<构建号>/failure-report.log，只归档该文件，成功继续归档游戏 ZIP 和清单。流水线在建立运行目录前失败时也能生成带参数和状态的报告，前提是工作区隔离校验已经通过。启动器捕获启动失败并写 runtime/failure-report.log，仅包含该次尝试的服务日志。

交付包含新便携 ZIP 和不含数据/凭据的更新包，并更新已部署 E:/fb 的可信脚本和 manifest（已确认无运行中服务后执行，需目录写入权限）。旧归档保持历史记录。验证涵盖完整文本、Unicode、无日志/空日志、调用栈、凭据遮盖、路径隔离、真实失败/成功流水线的归档数量和启动失败。源码和游戏逻辑不修改。
